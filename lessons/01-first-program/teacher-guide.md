# 教師指引｜第 1 堂：讓電腦說話

**對象：** 高一、沒有寫程式經驗的學生  
**時間：** 60 分鐘，包含 5 分鐘休息  
**作品：** 至少三行輸出的文字名片  
**本堂範圍：** `print()`、字串、由上而下的執行順序、`#` 註解，以及常見符號錯誤。

本堂先讓學生完成「我改了程式，電腦真的照著改」的體驗。變數留到第二堂，`input()` 留到第三堂；本堂不需要解釋資料型別、函式定義、條件或迴圈。

## 下課時，學生能做到什麼？

- 自己執行一個 Python 檔案，找到輸出結果。
- 用 `print("文字")` 顯示文字，並說出引號的作用。
- 預測多行 `print()` 的輸出順序，辨認整行註解。
- 找出並修正漏引號、漏括號或使用全形程式符號的錯誤。
- 製作至少三行、內容經過自己修改的文字名片。

## 課前準備

- 先確認每台電腦已能在 PyCharm 執行 Python 3；安裝與環境設定不要佔用本堂實作時間。
- 教師先用上課帳號執行一次 `print("準備好了！")`，確認中文能顯示。
- 準備可讓學生建立或開啟 `.py` 檔案的專案，並先打開教材與[學習單](worksheet.md)。
- 投影時放大程式字體，也讓學生看見下方的執行結果；清楚區分「寫程式的地方」與「看結果的地方」。
- 若學生尚不熟悉檔案操作，可先提供空白的 `my_card.py`；不要要求學生本堂先學 Git 或 GitHub 上傳。
- 電腦不足時可兩人一組，輪流擔任操作員與觀察員；每位學生至少實際修改並執行一次。

## 60 分鐘教學流程

| 時間 | 活動 | 教師引導 | 學生可見成果 |
| --- | --- | --- | --- |
| 0–5 分 | 暖身：電腦照順序做事 | 展示三行文字名片，問「如果交換兩行指令，畫面會怎麼變？」 | 知道今天的作品長相 |
| 5–15 分 | 示範第一支程式 | 打字、執行、找輸出，再換一句文字；介紹引號與括號 | 成功執行一行 `print()` |
| 15–23 分 | 排好輸出順序 | 先猜、執行，再交換兩行 | 能預測輸出順序 |
| 23–30 分 | 加入註解 | 用 `#` 留下提醒，觀察哪一行不顯示 | 能分辨文字與註解 |
| 30–35 分 | 休息 | 存檔、離開螢幕伸展，提醒休息後繼續作品 | 已保留目前進度 |
| 35–50 分 | 製作我的文字名片 | 提供三行基本骨架，逐步加上自己的內容與註解 | 至少三行的個人化作品 |
| 50–55 分 | 除錯偵探 | 一次修正一個引號或括號錯誤 | 能找到線索並重跑 |
| 55–60 分 | 展示與離堂檢核 | 第 1、2 題短答；第 3 題以自己的作品口頭回答 | 能說明修改與執行結果 |

### 0–5 分｜先看作品，再猜指令

展示簡單名片即可，不需要先秀複雜動畫：

```text
暱稱：小宇
興趣：畫畫
口頭禪：先試試看！
```

可說：「今天我們要教電腦介紹一個角色。角色可以是你，也可以是你發明的人物。」使用暱稱與虛構資料即可，不要求學生填真實姓名或聯絡資訊。

### 5–15 分｜示範要慢，讓每一步都看得見

先只輸入一行，執行後指出畫面上的結果：

```python
print("你好，Python！")
```

用三句話解釋：

1. `print` 請電腦把內容顯示出來。
2. 括號裡放想顯示的內容。
3. 引號把一段文字包起來；這種文字資料叫做「字串」。

### 15–30 分｜加入順序與註解

15–23 分：再加入第二行，請學生猜哪一句先出現：

```python
print("你好，Python！")
print("今天我完成了第一個程式。")
```

23–30 分：最後加入一行註解：

```python
# 這行是給讀程式的人看的提醒
print("你好，Python！")
print("今天我完成了第一個程式。")
```

說明：「這裡以 `#` 開頭的整行是註解，不會變成輸出。」本堂先採用整行註解，避免一次加入太多寫法。

這兩段都採固定節奏：先猜、執行、改一處、說明。

- 先猜：兩行會依什麼順序出現？
- 執行：找到結果，與預測比對。
- 改一處：換掉引號內的文字，或交換兩行 `print()`。
- 說明：請學生說「我改了哪裡，所以結果變成什麼」。

50–55 分鐘的除錯活動再示範一個漏引號的錯誤。先告訴學生這是刻意的除錯示範，再帶著他們看錯誤訊息的位置提示、回到程式檢查符號、修正、重新執行。不要要求初學者背英文錯誤名稱，也不要保證錯誤標記一定正好指在根源上。

巡堂先確認每位學生至少成功執行一次，再處理裝飾或排版。

### 35–50 分｜名片任務：先完成，再加個性

基本任務：用至少三行 `print()` 介紹角色的暱稱、興趣、口頭禪；在程式中加一行說明作品用途的 `#` 註解。

建議節奏：

- 前 5 分鐘：決定三項內容，寫出基本版本。
- 中間 7 分鐘：執行、檢查、修正，讓三行內容都正常出現。
- 最後 3 分鐘：與同桌交換檢查；有餘裕再加入文字框線或第四行介紹。

學生可用 `print("====================")` 加上框線，不需要使用乘法或其他尚未教過的語法。提醒作品不以裝飾多寡評分。

## 遇到錯誤時怎麼陪學生找？

先問「你預期看到什麼？現在看到什麼？」再一起檢查，不急著接手重打整份程式。

| 現象 | 可以引導學生檢查 |
| --- | --- |
| 引號相關錯誤 | 文字前後是否都有半形雙引號 `"`？ |
| 括號相關錯誤 | 左右半形括號 `(`、`)` 是否成對？ |
| 看起來都對，卻無法執行 | 程式符號是否變成 `（ ）` 或彎引號 `“ ”`？ |
| `Print` 無法使用 | 是否寫成小寫的 `print`？Python 區分大小寫。 |
| 某一行沒有出現 | 該行是否以 `#` 開頭？ |
| 改了內容，輸出沒變 | 是否重新執行了正在編輯的檔案？ |

中文文字與全形標點可以放在字串裡。例如 `print("你好！")` 的中文驚嘆號沒有問題；要檢查的是字串外的程式符號與包住文字的引號。

## 差異化與時間調整

- **還需要協助：** 提供完整三行骨架，只讓學生修改引號內的內容；每改一行就執行一次。
- **進度較快：** 加上框線、第四行角色介紹，或交換輸出順序並解釋結果；不提前加入變數、輸入或迴圈。
- **時間不足：** 省略裝飾與全班逐一展示，保留三行作品、同桌說明與離堂檢核。
- **環境暫時無法使用：** 先在學習單寫出程式與預期輸出，再與同桌共用電腦實際執行；紙上作答不取代執行驗證。

## 評量與課後回饋

最後 5 分鐘：第 1、2 題各用約 1 分鐘，第 3 題直接指著已完成名片口頭回答，不必重抄；再用 2 分鐘展示與存檔。學習反思可課後補填。

以四項可觀察證據檢查學習，不以打字速度評分：

- [ ] 能執行作品，產生至少三行名片內容。
- [ ] 至少一處內容是學生自己修改的，且能指出對應程式行。
- [ ] 有一行用途清楚的 `#` 註解，能說明它不會顯示在輸出中。
- [ ] 能完成離堂檢核，或在提示後修正並說明原因。

離堂檢核與學習單的[參考解答](solutions/README.md)分開放置。建議先請學生嘗試，再用答案討論理由。對仍混淆引號、順序或註解的學生，下次上課先給一個相同概念、不同文字的小題。

課後延伸維持同樣語法：把角色卡改成社團招募小卡、遊戲開場白或自己的三句鼓勵。只要學生能解釋每一行，就已達成本堂目標。
